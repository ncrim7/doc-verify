# Measurement — 2026-09-02 · Phase-1 baseline

First authoritative accuracy run on the regenerated corpus. Single pass, no
tuning after seeing the result (per the project rule). This is the number to
quote for Phase 1.

## Setup

| | |
|---|---|
| Model | `gpt-5-nano` (strategy `direct`, `temperature` unset) |
| Pipeline | extract → rule-verify + auto-correct → correction-agent → evaluate |
| Corpus | 60 synthetic docs, `seed=42` (20 invoice / 20 PO / 20 receipt), `data/processed/measure_manifest.json` |
| Command | `python scripts/run_full_pipeline.py --model gpt-5-nano --strategy direct --split measure --delay 0.3 --checkpoint` |
| Runtime | ~23 min (~15–35 s/doc; gpt-5-nano is a reasoning model) |
| Cost | ~$0.05 estimated (~1.6k input + ~2k output tokens/call × 60). Exact figure in the Langfuse dashboard. |
| Raw result | `2026-09-02-baseline.results.json` (this folder) |

## Result

| Stage | Field-level EM | Semantic sim | Token F1 |
|---|---|---|---|
| Baseline (raw extraction) | **96.10%** | 99.11% | 97.92% |
| Verified (+ rule auto-correct) | 96.10% | 99.11% | 97.92% |
| Corrected (+ correction agent) | 96.10% | 99.11% | 97.92% |

- **58 of 60 docs** contributed; 2 produced no result (see Defects). Counting
  those 2 as 0% gives **92.9%**.
- Per type: invoice 96.0% (n=19) · PO 95.8% (n=19) · receipt 96.5% (n=20).
- Distribution: 20/58 docs scored a perfect 1.0; lowest was PO_0011 at 0.842.

**Semantic similarity 99.11% / token F1 97.92%** is the "is this usable"
signal — the extractions are almost entirely correct in meaning; strict EM is
lost on character-level Turkish-suffix differences (below).

## Defects found (→ Phase 2 backlog)

### D1 — 2 silent extraction failures (correctness bug)

`invoice_0017`, `po_0001`: HTTP 200, but the response would not parse as JSON;
the pipeline logged a warning, returned `{}`, and moved on. Almost certainly
the gpt-5-nano reasoning-token budget: `max_completion_tokens=4096` covers
reasoning + output, and on these two docs reasoning left too little for a
complete JSON object.

Impact in production: ~3.3% of documents silently not processed.

Fix candidates: `reasoning_effort="minimal"` (also cuts the 15–35 s latency),
a retry when `_parse_json_response` returns `None`, a larger token ceiling.

### D2 — systematic field errors (the ~4% EM gap)

Not scattered noise — three named patterns:

| Field | Misses (of 58) | Pattern |
|---|---|---|
| `description` | 46 | Turkish suffix dropped: `Ağ Anahtarı`→`Anahtar`, `Bandı`→`Band`, `Geniş`→`Geni`, `Deterjanı`→`Deterjan`, `Lisansı`→`Lisans`, `Dezenfektanı`→`Dezenfektan`. Also anglicisation: `Spagetti`→`Spaghetti`; quote mangling `(16'lı)`→`(16'')`. |
| `buyer_address` | 13 | Tail truncation: `…Suite 451, Erdoğ…` → `…Suite 45`. Long Faker US-format addresses fall below the 0.80 fuzzy-match threshold. |
| `currency` | 6 | `TRY`→`USD` on English-labelled docs (no ₺ symbol; the model guesses). SYSTEM_PROMPT already has a rule; not enough for nano. |
| `vendor_tax_id` / `buyer_tax_id` | 4 | minor — occasional digit / Turkish-char slip (`Korutürk`→`Korütürk`). |

Note: the D2-added item catalog is deliberately Turkish-suffix-dense, which
maximised exposure to the `description` failure mode. Some misses
(`Spagetti`/`Spaghetti`) are near-synonyms a human reviewer would accept.

Fix candidates: a "copy the description verbatim, preserve every Turkish
suffix, do not translate or normalise" instruction; currency rule hardening;
realistic Turkish address templates (also improves demo optics).

### D3 — self-verification added nothing here

Rule verifier: **0 issues, 0 auto-corrections, 0 correction-agent calls** across
all 58. `arithmetic_repair` runs inside `extract()`, so the math is already
consistent by the time the verifier sees it, and gpt-5-nano populated every
required field. Baseline == verified == corrected.

This matches the thesis finding (RQ3): on clean data the verification layer is
a production QA net for dirty input, not an accuracy lever. Its value shows on
degraded scans / real documents, not this synthetic set.
